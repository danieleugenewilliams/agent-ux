# agent-ux: the outcome

*Draft by Claude for Daniel to rewrite in his own words. The loop reads this file; only
Daniel edits it.*

agent-ux is a set of browser games for our family, made with and for the boys. Each game is
one HTML page that opens on a phone, an iPad or a computer and works from GitHub Pages. They
are games the boys want to play, and several of them carry something to learn inside the
play: multiplication and division facts in Robot Battle, spelling in Wild World, and the
boys' own design ideas in Neon Dash.

## How we'd know

- The boys choose to play without being asked, and keep coming back.
- A game opens and plays straight from GitHub Pages, on the devices they actually use: a
  phone held sideways, an iPad, a keyboard, a gamepad.
- Where a game teaches, the learning is part of the fight or the adventure, not a quiz in the
  way of it.
- Progress a child has earned is never lost or corrupted by an update.
- A parent can see how a game is going (progress, practice) without the children wandering
  into the parent view.
- Their own ideas show up in the games the way they asked for them.

## Not the goal (for now)

- Anything that leaves the browser: no accounts, no outside servers, no analytics, no names
  sent anywhere. The one exception is Wild World's two-player game server, which runs only on
  the Mac on the home Wi-Fi.
- A child's name, grade or reading level anywhere in a game, test, issue, PR or commit
  (#161). Players make their own profiles in the game.
- Commercial release. Games inspired by commercial titles are unofficial, non-commercial fan
  projects that use none of the original assets.

## Each game's own outcome

A game can have its own outcome file under `docs/<game>/`. A pull request that changes that
game is read against its file as well as this one.
